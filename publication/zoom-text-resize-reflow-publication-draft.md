# Zoom, Text Resize & Reflow

Page zoom enlarges the rendered page. Text resizing lets people make the text larger. Reflow is how content rearranges to fit the available space so people can read and interact without scrolling in two directions.

## What are the two WCAG checks?

| WCAG criterion | What to verify |
|---|---|
| **1.4.4 Resize Text, Level AA** | Text can be enlarged up to **200%** without loss of content or functionality and without requiring assistive technology. Captions and images of text are exceptions. Browser zoom is one way to provide text resizing. |
| **1.4.10 Reflow, Level AA** | Vertically scrolling content works at a width equivalent to **320 CSS pixels**, without loss of information or functionality or the need to scroll in two directions. For content designed to scroll horizontally, the corresponding height is **256 CSS pixels**. Parts that require a two-dimensional layout for use or meaning are excepted. |

## Example: A booking form with a fare table

At 200% text enlargement, check that field labels and validation errors remain readable and that users can activate the Continue button. At a 320 CSS-pixel width, let the form fields stack and keep the Continue button reachable. If a sticky bar covers errors or makes the remaining viewport too small, let the bar scroll with the form at that layout.

If the fare table needs row and column relationships to make sense, it can scroll within its own region. Keep surrounding content within the page width and let text within individual cells wrap where it can.

## How do you test reflow?

Start with a desktop browser viewport 1,280 CSS pixels wide and zoom to 400% to reach the equivalent of 320 CSS pixels. Check the actual viewport and complete the task, including error recovery. For the separate resize-text check, verify that text can reach twice its original size. If a responsive breakpoint reduces the base font size at higher zoom, compare the resulting visual size with the original.
