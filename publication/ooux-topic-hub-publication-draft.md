# OOUX and ORCA

Explore the OOUX and ORCA glossary through the questions a product team needs to answer: what people work with, how those things connect, what users can do, and what information they need.

Start with [Object-Oriented UX](/glossary/object-oriented-ux.html) for the design approach and [ORCA Framework](/glossary/orca-framework.html) for the four iterative rounds. Then follow the [worked booking example](/glossary/ooux-worked-example.html) to see how the pieces fit together.

## Discover the product's structure

Use [Noun Foraging](/glossary/noun-foraging.html) to identify candidate objects from research. Investigate connections with a [Nested Object Matrix](/glossary/nested-object-matrix.html), actions with a [CTA Matrix](/glossary/cta-matrix.html), and information through [Object Mapping](/glossary/object-mapping.html).

[Object Attributes in OOUX](/glossary/object-attributes-ooux.html) explains core content, metadata, and the distinction between a field and a related object.

## Clarify requirements

An [Object Guide](/glossary/object-guide.html) records what each object means. [ORCA Relationship Requirements](/glossary/orca-relationship-requirements.html) examines how connections work, while [Cardinality](/glossary/cardinality-ux-architecture.html) clarifies permitted counts in both directions.

[Object-Oriented User Stories](/glossary/object-oriented-user-stories.html) develops the reason and conditions for an action. A [State Transition Matrix](/glossary/state-transition-matrix.html) can document the lifecycle behind it.

## Prioritize the release and the experience

These four activities address related decisions:

| Activity | Question |
|---|---|
| [Object Prioritization](/glossary/object-prioritization.html) | Which things need support, and how will users reach them? |
| [Relationship Prioritization](/glossary/relationship-prioritization.html) | Which connections and navigation paths matter for the task? |
| [CTA Prioritization](/glossary/cta-prioritization.html) | Which actions need support and prominence in this context? |
| [Attribute Prioritization](/glossary/attribute-prioritization.html) | Which information helps users identify, compare, and act? |

## Represent and test the model

[Object Representation](/glossary/object-representation-ooux.html) connects the model to cards, lists, and detailed views. A [Shapeshifter Matrix](/glossary/shapeshifter-matrix.html) helps document intentional variants.

Use the [Four UX Fails in OOUX](/glossary/ooux-ux-fails.html) as a diagnostic lens, [Content Prototyping](/glossary/content-prototyping.html) to populate the model, and [OOUX Prototyping and Testing](/glossary/ooux-prototyping-and-testing.html) to observe recognition, navigation, and action understanding.

## Work through more complex models

A [Junction Object](/glossary/junction-object.html) can represent a connection with its own information. [Tree Systems](/glossary/tree-systems-ooux.html) describes related forms that become more specific in context. [Object Inheritance in OOUX](/glossary/object-inheritance-ooux.html) examines general types and meaningful subtypes.

For surrounding practices, explore [Content Modeling](/glossary/content-modeling.html), [Domain Context Modeling](/glossary/domain-context-modeling.html), and [Structural Navigation Model](/glossary/structural-navigation-model.html).

To plan collaborative work, see [ORCA Sprint](/glossary/orca-sprint.html). Choose a bounded problem and use the relevant tools; revisit research whenever the model exposes an unanswered question.
