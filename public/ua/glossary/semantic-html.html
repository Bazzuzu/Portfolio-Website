Семантичний HTML (Semantic HTML)

Дизайн-системи та інженерія • UX та архітектура продукту

Семантичний HTML полягає у виборі HTML-елементів відповідно до смислового значення та призначення контенту й елементів керування. Елементи на кшталт заголовків, посилань, кнопок та підписів форм передають браузерам інформацію про структуру сторінки та про те, як користувачі можуть із нею взаємодіяти.

Як семантичний HTML підтримує доступність?

Браузер використовує семантику HTML, щоб передавати таку інформацію, як ролі, доступні імена та стани елементів, через своє дерево доступності (accessibility tree). Програми зчитування з екрана (screen readers) використовують цю інформацію, щоб ідентифікувати кнопку або здійснювати швидку навігацію за заголовками. Тег є посиланням для переходу за адресою. Нативна кнопка

Приклад: Форма запиту вартості

<form action="/quote" method="post">
  <label for="quote-email">Email address</label>
  <input id="quote-email" name="email" type="email" required>
  <button type="submit">Request a quote</button>
</form>

Текстовий підпис () задає ім'я поля, а текст кнопки описує, що відбудеться після активації. У реальному робочому процесі перевірте, чи можуть користувачі легко виправити помилки валідації та чи отримують вони чітке підтвердження успішного надсилання форми.

Чим це допомагає ШІ-агентам браузера?

Деякі браузерні ШІ-агенти (AI browser agents) використовують дерево доступності для дослідження вмісту сторінки. Наприклад, бенчмарк WebArena фіксує спостереження за деревом доступності поруч із діями агента. Агент, що спирається на це представлення, може шукати поле електронної пошти та кнопку «Request a quote». Інші агенти можуть аналізувати безпосередньо структуру DOM або діяти на основі знімків екрана, тому тестуйте виконання наскрізного завдання саме з тим агентом, який є пріоритетним для вашого продукту.

Пошукова оптимізація та індексація — це окреме питання. Для роботи ШІ-функцій у пошуку Google цільова сторінка повинна бути проіндексована та мати право на показ розширеного сніпета. Google не вимагає спеціальної розмітки суто для цих інструментів і вибирає опорні сторінки індивідуально для кожної відповіді.

Пов'язані терміни

  • Доступність веб-інтерфейсів (WCAG)
  • ARIA (Accessible Rich Internet Applications)
  • Веб-компоненти (Web Components)
  • Структуровані дані для LLM

Джерела

  • Розділи, Живий стандарт WHATWG HTML (Sections, WHATWG HTML Living Standard)
  • Форми, Живий стандарт WHATWG HTML (Forms, WHATWG HTML Living Standard)
  • Маркування елементів керування, W3C WAI (Labeling Controls)
  • Трасування виконання агентів WebArena (WebArena Agent Execution Traces)
  • Функції ШІ та ваш вебсайт, Google Search Central (AI Features and Your Website)
