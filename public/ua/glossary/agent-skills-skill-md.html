Навички агентів (SKILL.md)

ШІ та агентні системи • Дизайн-системи та інженерія

Навички агентів (Agent Skills) — це повторно використовувані пакети інструкцій та допоміжних ресурсів, які допомагають сумісним ШІ-агентам виконувати конкретні завдання. У форматі Agent Skills кожна навичка являє собою каталог із файлом SKILL.md, а також додатковими скриптами, довідковими матеріалами та ресурсами.

У файлі SKILL.md використовується YAML frontmatter для опису метаданих, за якими слідують інструкції у форматі Markdown. Специфікація вимагає наявності назви (name) та опису (description). Сумісні агенти можуть використовувати цей опис для виявлення релевантних навичок і підвантажувати подальші детальні інструкції лише за потреби; підтримка залежить від конкретної реалізації агента.

Приклад: підготовка запису для глосарія

Навичка публікації може описувати умови її використання, обов'язкові метадані, прийнятий на сайті формат Markdown та перевірки, необхідні перед випуском матеріалу. Довідковий файл може містити приклад схеми сайту, тоді як скрипт валідує готовий документ.

Інструкції повинні чітко визначати очікувані вхідні та вихідні дані, пояснювати правила обробки відсутньої інформації та фіксувати моменти, коли агент зобов'язаний зупинитися й запитати рішення в людини. Приклади мають бути достатньо конкретними, щоб ефективно спрямовувати виконання завдання.

Навички, інструменти та MCP

Ці концепції мають різне призначення:

  • Навичка (Skill) описує повторно використовуваний порядок і правила виконання роботи.
  • Інструмент (Tool) надає атомарну операцію, яку може виконати застосунок.
  • MCP (Model Context Protocol) забезпечує стандартний протокол для підключення ШІ-застосунку до зовнішніх можливостей, як-от інструментів і ресурсів.

Навичка може пояснити агенту, як саме викликати інструмент, наданий через MCP. Проте вона сама по собі не надає доступу до облікового запису і не гарантує безпеку виконання операції.

Ретельно перевіряйте скрипти та зовнішні ресурси перед їх використанням. Тестуйте навичку на неповних вхідних даних та реалістичних сценаріях збоїв. Версіонуйте інструкції, щоб будь-який отриманий результат можна було чітко зіставити з використаною версією процедури.
