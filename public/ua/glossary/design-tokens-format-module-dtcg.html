Формат дизайн-токенів DTCG

Дизайн-системи та інженерія • UX та архітектура продукту

Модуль формату дизайн-токенів (Design Tokens Format Module) — це специфікація від Design Tokens Community Group (DTCG), призначена для стандартизованого обміну дизайн-токенами у форматі JSON. Вона визначає правила опису іменованих токенів, груп, типів, значень та посилань (references). Робоча група класифікує версію 2025.10 як стабільну (stable). Це специфікація спільноти (Community Group Report), опублікована поза офіційним процесом стандартизації W3C Standards Track.

Як виглядає токен у форматі DTCG?

У наведеному нижче прикладі специфікації 2025.10 згруповано два токени тривалості в групі motion. Базова тривалість становить 150 мілісекунд. Токен візуального відгуку повторно використовує її за посиланням.

{
  "motion": {
    "$type": "duration",
    "fast": {
      "$value": { "value": 150, "unit": "ms" }
    },
    "feedback": {
      "$value": "{motion.fast}"
    }
  }
}

Базовий токен motion.fast успадковує тип тривалості (duration) від батьківської групи. Токен motion.feedback отримує тип від токена, на який він посилається. Посилання у фігурних дужках вказує на токен motion.fast, завдяки чому motion.feedback резолвиться в те саме значення тривалості — 150 мілісекунд. Група motion структурує токени, а кожен дочірній токен містить власну властивість $value.

Що охоплює модуль формату (Format Module)?

Модуль формату визначає структуру обміну даними та правила її інтерпретації. Він регламентує підтримувані типи даних, зокрема складені (composite types), які об'єднують пов'язані властивості в єдине значення (наприклад, параметри шрифту чи тіні). Окремий модуль резолвера (Resolver Module) описує алгоритми обчислення значень токенів для різних контекстів, таких як світла чи темна тема.

Використовуйте цей формат для безшовної передачі даних між різними дизайн-інструментами та платформами розробки. При цьому саме ваша команда визначає таксономію токенів, систему семантичного найменування та регламент внесення змін. Пайплайн збірки платформи трансформує обчислені значення у файли, необхідні клієнтським застосункам.

Як перевірити сумісність інструментів (interoperability)?

Виберіть невеликий репрезентативний набір реальних токенів і перевірте, що кожен інструмент здатен коректно імпортувати, резолвити та експортувати. Включіть різні типи даних, які ви використовуєте, а також перехресні посилання між групами. Якщо робочий процес підтримує теми, перевірте ту саму семантичну роль у двох різних контекстах. Порівняйте фінальні згенеровані значення з тими, що очікуються застосунком. Обов'язково протестуйте стійкість до розірваних (broken) та циклічних (circular) посилань.

Фіксуйте версію специфікації та будь-які специфічні розширення (extensions), від яких залежить ваш пайплайн. Валідний JSON-файл повинен неухильно відповідати правилам формату DTCG. Якщо інструмент втрачає посилання або замінює його жорстко закодованим літералом під час експорту, перевірте, чи отримує наступний інструмент у ланцюжку всю необхідну інформацію.
