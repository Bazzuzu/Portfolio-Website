Флюїдна типографіка та система відступів

Дизайн-системи та інженерія • UX та архітектура продукту

Система флюїдної типографіки та відступів плавно масштабує розміри тексту й інтервали макета у визначених межах залежно від зміни доступного розміру в'юпорта або контейнера. Вона спирається на скоординований набір математичних правил замість розрізнених фіксованих значень для кожної ширини екрана.

Флюїдні значення можуть гармонійно співіснувати з брейкпоїнтами. Макет може змінювати свою структуру на точці перелому, тоді як обрані розміри безперервно підлаштовуються між мінімальним і максимальним значеннями.

Приклад на CSS

Функція CSS clamp() приймає мінімальне значення, бажане значення (preferred value) та максимальне значення:

:root {
  --text-heading: clamp(2rem, calc(1rem + 3vw), 4rem);
  --space-section: clamp(0.75rem, calc(0.5rem + 1vw), 1.5rem);
}

h1 {
  font-size: var(--text-heading);
}

section {
  padding-block: var(--space-section);
}

Тут динамічний внесок в'юпорта змінюється разом із шириною екрана, тоді як значення в rem прив'язані до кореневого розміру шрифту. Ці значення є наочною ілюстрацією для тестування в конкретному контексті, а не універсальною шкалою.

Що необхідно тестувати?

Перевіряйте поведінку на проміжних значеннях ширини екрана так само ретельно, як і на крайніх точках. Тестуйте довгі заголовки, перекладені локалізовані написи, компактні елементи керування та реалістичний контент.

Зважено використовуйте відносні одиниці вимірювання та перевіряйте масштаб у браузері й користувацькі налаштування розміру шрифту. Просте комбінування rem з одиницями в'юпорта автоматично не гарантує доступного масштабування тексту.

Критерій доступності WCAG 2.2 «Зміна розміру тексту» (Resize Text) зазвичай вимагає, щоб розмір тексту міг збільшуватися до 200% без втрати контенту чи функціональності (з урахуванням стандартних винятків). Критерій «Перекомпонування» (Reflow) є окремою вимогою з чітко визначеними умовами для в'юпорта та винятками для контенту, що потребує двовимірного розташування.

Слідкуйте за тим, щоб довжина рядка, висота рядка, індикатори фокусу та клікабельні зони залишалися зручними при змінах макета. Не допускайте ситуацій, коли флюїдна шкала робить критично важливий текст або елементи керування занадто дрібними.
