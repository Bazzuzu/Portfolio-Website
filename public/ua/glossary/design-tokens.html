Дизайн-токени (Design Tokens)

Дизайн-системи та інженерія • UX та архітектура продукту

Дизайн-токени — це іменовані значення, що інкапсулюють повторно використовувані візуальні та дизайн-рішення, такі як кольори, відступи, типографіка та анімація. Вони надають дизайнерам і розробникам єдину спільну мову для опису та застосування цих рішень у компонентах, темах і платформах.

Наприклад, компонент може використовувати токен з назвою color.text.link замість довільного вибору кольору. Назва визначає функціональне призначення, а його значення може динамічно змінюватися залежно від поточної теми.

Що таке примітивні, семантичні та компонентні токени?

Багато дизайн-систем структурують токени за рівнями абстракції. Найменування та кількість рівнів можуть варіюватися залежно від потреб системи.

Рівень Показовий приклад назви Роль і призначення
Примітивний (Primitive) color.blue.600 Зберігає базове значення палітри.
Семантичний (Semantic) color.text.link Призначає значення під конкретну функціональну мету.
Компонентний (Component) button.primary.background Застосовує дизайн-рішення до конкретного компонента.

Семантичний токен може посилатися на примітивний через механізм аліасів (aliases). Наприклад, color.text.link може посилатися на color.blue.600 у світлій темі та на світліший відтінок синього в темній темі. При цьому компоненти продовжують використовувати незмінну семантичну назву. Завжди перевіряйте підсумковий коефіцієнт контрастності в кожному контексті.

Простий приклад дизайн-токена

У цьому прикладі використовується формат специфікації DTCG 2025.10 для визначення значення відступу та токена внутрішніх полів картки:

{
  "space": {
    "200": {
      "$type": "dimension",
      "$value": { "value": 8, "unit": "px" }
    }
  },
  "card": {
    "padding": {
      "$type": "dimension",
      "$value": "{space.200}"
    }
  }
}

Токен card.padding резолвиться у значення 8 пікселів завдяки посиланню на {space.200}. Якщо потрібно збільшити відступ виключно для карток, достатньо спрямувати card.padding на інший токен відступу. Зміна ж самого токена space.200 вплине на кожен токен, який на нього посилається. Назви та значення наведені для ілюстрації.

Як токени переходять із дизайну в код?

Команда веде єдине джерело істини для визначень токенів у погодженому репозиторії, здійснює код-рев'ю змін і використовує спеціалізовані інструменти збірки для генерації артефактів під цільові платформи. Інструменти на кшталт Style Dictionary трансформують дані токенів у змінні CSS (custom properties), константи JavaScript або нативні ресурси платформ (iOS, Android).

Користувацькі властивості CSS (CSS custom properties) та змінні Figma (Figma variables) представляють токени у своїх відповідних середовищах. Єдина схема найменування, сумісні інструменти та прозорий процес релізів об'єднують їх у цілісний пайплайн. Самі по собі токени не забезпечують автоматичну синхронізацію файлів дизайну та продакшн-коду без налаштованого тулінгу.

Чи обов'язково дизайн-токени мають бути у форматі JSON?

Токени — це концептуальний патерн архітектури дизайн-систем; специфікація DTCG визначає стандартизований формат JSON для взаємодії та обміну даними між різними інструментами. Стабільний модуль формату (Format Module) версії 2025.10 визначає типи, значення, групи та посилання. Це специфікація Спільноти (Community Group), а не офіційний стандарт Рекомендації W3C (W3C Standard).

Починайте з рішень, які повторюються по всьому інтерфейсу. Документуйте цільове використання та перевіряйте залежні компоненти перед випуском змін. Додавайте нові рівні абстракції лише тоді, коли вони вирішують конкретні завдання перевикористання або супроводу.
