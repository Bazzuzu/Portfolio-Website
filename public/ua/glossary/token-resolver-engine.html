Двигун обчислення токенів (Token Resolver)

Дизайн-системи та інженерія • UX та архітектура продукту

Двигун обчислення токенів (Token Resolver Engine) — це програмне забезпечення, яке визначає, які саме значення застосовуються до дизайн-токенів у певному контексті, наприклад, у світлій чи темній темі. Він може об'єднувати джерела токенів у визначеному порядку та розгортати ланцюжки посилань (references), формуючи фінальні значення для інструментів-споживачів.

Що робить резолвер токенів?

Формат дизайн-токенів DTCG (Format Module) визначає значення токенів та посилання між ними. Окремий модуль Resolver Module визначає, як обирати та комбінувати джерела для контексту. Наприклад, документ резолвера може перелічувати базовий набір, а потім модифікатор теми у resolutionOrder. Вхідні дані обирають контекст, такий як dark, для цього модифікатора. За правилами черговості Resolver Module, якщо обрані джерела декларують один і той самий токен більше одного разу, перемагає остання декларація.

Вибір контексту та аліас (alias) відповідають на різні запитання. Контекст визначає, яка саме декларація color.text.link застосовується. Аліас вказує на токен палітри, значення якого має використати посилання.

Приклад обчислення кольору посилання

Припустімо, що Base визначає як кольори палітри, так і стандартну роль для посилання. Модифікатор теми не додає джерел для Light і додає одне джерело, Dark, для темного режиму.

Контекст Джерела, застосовані за порядком Переможне посилання для color.text.link
Light Base {color.blue.600}
Dark Base, потім Dark {color.blue.300}

Палітра присутня в обох результатах, оскільки кожен контекст містить Base. Після визначення переможної декларації перейдіть за її посиланням до відповідного значення кольору. Компонент продовжує використовувати ту саму роль посилання.

Що необхідно тестувати?

  • Порядок джерел (Source order). Переконайтеся, що вибір Dark дійсно перекриває базове значення. Якщо значення не змінилося, перевірте, чи не було Base застосовано після Dark.
  • Посилання (References). Перевірте, чи існує цільовий токен у фінальному наборі та чи не утворюють аліаси цикл. Якщо цільовий токен відсутній, почніть із перевірки того, які джерела були обрані.
  • Результат для споживачів (Consumer output). Перевірте очікуване значення в обох контекстах. Інструмент збірки може генерувати літеральне значення або зберігати аліас у форматі платформи, якщо вона це підтримує.

Обчислення (resolution) визначає, що саме застосовується. Форматування визначає, як ці рішення представляються (наприклад, у вигляді кастомних властивостей CSS). Один інструмент може виконувати обидві задачі, або ви можете запускати окремий резолвер перед збіркою для цільової платформи.
